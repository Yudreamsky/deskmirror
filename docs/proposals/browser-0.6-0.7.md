# 浏览器版 0.6.0–0.7.1 的改动：桌面版跟不跟、怎么跟

浏览器版（[deskmirror-browser](https://github.com/Yudreamsky/deskmirror-browser)）最近三个版本的改动，逐条对照桌面版现在的代码（origin/main 93743c2，1.2.0）写清楚：

- 用户看到什么；
- 浏览器版是怎么做的（附代码链接）；
- 桌面版要改哪些文件；
- 哪些地方要拍板，以及我的建议。

这份文档只是方案，不改程序。桌面版的会话可以直接在这个分支上接着实现，也可以把各条拆成 issue。

## A. 抓手：拖到屏幕边缘吸成半球（#8 的升级版）

### 用户看到的（浏览器版 0.7.0）

用户的原话：“标题栏上加一个很明显的抓手让鼠标拖拽，拖到浏览器页面边缘自动动画吸附，变成半球，这时候停止翻译，也可以用鼠标从吸附状态拖出来，这时候有一个球变成虚线框的丝滑动画，同时启动翻译，这样比较符合操作直觉。”

- **抓手**：标签左头有一个六个点的抓手，鼠标悬停或按住时变蓝。整个标签照样能拖。
- **拖到边缘**：拖着魔镜，鼠标离左边或右边不到 28 px 时，镜框平滑地缩成直径 46 px 的小球，吸在那条边上，**翻译停下**。松手后，球马上藏进边缘约四成。
- **从边上拖出来**：按住球往外拖，离边缘超过 96 px 时，球平滑地张开成**虚线框**跟着鼠标走，**翻译同时开始**。
  - 抓手一直在鼠标底下，框不会出屏幕。
  - 拖的时候框里已经能看到译文。
  - 松手，虚线框落定成实线魔镜。
  - 拖回边缘又会缩成球，一次拖动里可以来回变。
- **点一下球**：魔镜回到吸附前的位置和大小。
- **标签上的“–”**：也能收成球，吸到较近的一边。球完整露出 1.6 s 后藏进去一点，鼠标移上去会滑出来。用户确认过要这样。

它取代了 0.5 的做法：以前气泡拖到哪里松手，就吸到较近的一边。现在球只待在边上，拖离边缘就变回魔镜。

### 浏览器版怎么做的

- **一套手势同时管镜框和球**：[`_gesture`][frame]（第 685 行），监听挂在整个窗口上，因为被拖的元素中途会隐藏。判断鼠标离哪条边多近的是 `_edgeOf`（第 749 行）。
- **两个门槛防抖**（[第 19–25 行][frame]）：
  - 离边缘 28 px 以内吸成球（`ZONE`），离开 96 px 才变回框（`ZONE_OUT`）；
  - 吸住时往里拖，球最多跟出来 36 px（`PULL`），像被边缘吸着。
- **每帧向目标靠一截，不用固定时长的动画**：
  - [`_liveRun` / `_liveStep`][frame]（第 891 行起）每帧计算 `f = 1 − exp(−dt/τ)`，其中 τ = 60 ms、dt 最多算 50 ms；
  - 让当前的 x、y、w、h 和圆度 k（0 是方框、1 是圆）各往目标走 f 那么多；
  - 目标随鼠标变化，中途可以反向，和帧率无关；
  - 差不到 0.4 px（k 差不到 0.004）就算到位。
- **译文跟着形状裁剪**：变形时，镜内译文的显示范围随圆角矩形一起缩成圆，而不是突然消失。
- **记住原位**：拖到边缘吸住以后，魔镜的位置记成开始拖之前的样子，以后点开球会回到原处（见 `_dock`，第 825 行）。
- **防止刚吸住又弹出来**：吸住后 700 ms 内不理会“鼠标移上来”，因为球从鼠标底下滑进边缘时，浏览器会补发一次悬停（见 `_untuck`）。
- **实测数据**：
  - 虚线框张开分了 105 帧，最长帧间隔 9–17 ms；
  - 吸成球分了 48 帧；
  - 测试是 [tests/bubble.mjs](https://github.com/Yudreamsky/deskmirror-browser/blob/a8bc44ff9081e70562a0075c7b76b1e4888ee6b2/tests/bubble.mjs)，逐帧取样形状、量帧间隔。
- **踩过的坑**：
  - 动画元素上不要加大面积的模糊阴影，那样每帧都要重画，帧时间会到 42 ms；
  - 液态玻璃的边缘折射用置换贴图做，要从边缘往里取样，往外取样会读到框外，出现白色月牙。

### 桌面版要改的地方

- **手势**：`ui/mirror.py` 的 `MirrorFrame`。
  - `_zone` 加抓手的点击区，`_paint_tab` 画抓手；
  - `mousePressEvent` / `mouseMoveEvent` / `mouseReleaseEvent` 里，拖标签（zone `tab`）时加上判断边缘、变形的逻辑；
  - 屏幕范围从 `_screen_for` 取。
- **动画画在哪**：建议画在 `ui/overlay.py` 每个显示器那张铺满屏幕的覆盖层上。
  - 这样窗口不动、也不改大小，只重画变化的区域。现在移动魔镜也是这样，只改裁剪范围。
  - 变形期间 `MirrorFrame` 先藏起来；球用一个小窗口接鼠标。
  - 不建议每帧改窗口大小：分层窗口每帧改尺寸，开销大，容易闪。
- **Windows 10**：色键窗口（`ui/layered.py`）只有完全透明和完全不透明两种像素，球的边缘会有锯齿。要么接受，要么预先画一张不需要半透明的球的图片。
  - 对截屏隐身要一直有效，免得识别把动画中间帧当成文字（#8 也提了）。
- **吸住就暂停**：现在“暂停”走 `app.py` 的 `_apply_working()` → `engine.set_working(False)`。
  - 吸住时同样停下：加一个 `docked` 状态，并进 `_apply_working` 的条件；
  - 拖出来时 `set_working(True)`，和“继续”一样重新核对画面。
  - 注意：现在标签上的“—”（隐藏）不会停下引擎。`_apply_working` 不看 `hidden`，隐藏后照样截屏、识别、翻译。
- **多显示器**：只吸附当前显示器的外边缘，两块屏相接的边不算（#8 的要求）。门槛 28 / 96 / 36 px 按 DPI 缩放，全程用物理像素（现有规则）。
- **记住状态**：吸在哪条边、球的高度、吸附前的矩形，存进 `config.py`。现有的 `mirror_rect` / `extra_mirrors` 保持存吸附前的位置。重启后还是吸着的状态；分辨率变了要校正到看得见的地方。
- **多个魔镜**：每个魔镜各自有球（#8 的要求）。
- **定时**：用 `QTimer`（约 16 ms）加 `time.perf_counter()` 算 dt，套用上面那个公式；不要用固定时长的 `QPropertyAnimation`，那样跟不上鼠标、也没法中途反向。

### 要拍板的

1. **球能不能离开边缘单独停着？** 建议**不能**，照 0.7.0：球只在边上，拖离边缘就是魔镜。这是用户在浏览器版定的，两个版本手感一致。另一个选项是 #8 原文“气泡可以拖到任意位置，靠边才吸附”，和 0.7.0 冲突。
2. **吸附哪几条边？** 建议**只吸左右两边**。底边常放字幕区，用户把魔镜拖到字幕上时容易误吸；顶边上方就是标签。#8 写的是上下左右四条边。
3. **吸住时停止翻译？** 建议**停**，和浏览器版、#8 的建议一致，不花 token。
4. **标签上的“—”做什么？** 现在是隐藏到托盘。建议改成“收成球吸到边上”，和浏览器版一样；隐藏留给快捷键和托盘菜单。藏到托盘的魔镜不容易找回来。
5. **球上显示什么？** 浏览器版是鼠标停在球上时，提示里显示这次的 token 用量。桌面版已经有当天的 ↑↓ token（#6），建议放进球的提示里。
6. **液态玻璃皮肤**：照 #8 原样做。上面“踩过的坑”里两条可以直接用。

### 验收

- 拖到左右边缘吸成球、从边上拖出来变虚线框、松手落定、中途反向，都是 60 fps。逐帧量形状和帧间隔，参照 tests/bubble.mjs。
- 吸住以后不再有新的翻译请求（看用量日志或引擎计数）；拖出来几秒内译文恢复。
- Windows 10（色键窗口）和 Windows 11 都试；多显示器只吸外边缘；重启后状态还在。

## B. 输入框翻译：连按三次空格翻译，再按三次换回原文

### 用户看到的（浏览器版 0.6.0 + 0.7.1）

- 在输入框里打完母语，连按三次空格，整个框换成设置里“输入框翻译成”的语言。默认是母语为英文时译成中文，否则译成英文。
- **再连按三次空格换回原文，再按又换成译文**，可以一直来回切。来回切用记住的文字，不发请求、不花 token。
- 用户提的需求：“输入框三次空格……再三次空格应该切换回去，刚好原文也有缓存”。
- 以下情况会重新翻译：
  - 换回原文后改了字；
  - 设置里换了“输入框翻译成”的语言；
  - 上次有段落没译出来。
- 输入框旁边有小提示：“翻译中…”“已翻译 · 再连按三次空格换回原文”“已换回原文 · 再连按三次空格换成译文”，失败时写原因。Ctrl+Z 照样能撤回。
- 用户定的：**输入框里打的一定是母语**（“一般输入是母语”“这个是确定的”）。请求里直接说明原文是什么语言，不让模型猜。

### 浏览器版怎么做的（[field.js][field]）

- **什么时候触发**（[`onKey`][field]，第 320 行）：
  - 每两下空格之间不超过 500 ms；
  - 不算按住不放的自动连发、输入法正在选字时的空格（keyCode 229）、带修饰键的空格；
  - 光标要在最后，三个空格前面有字，而且不在行首（行首连按空格多半是在缩进）；
  - 真正翻译前再核对一次框里的字是不是以三个空格结尾，输入法吃掉的空格就不会误触。
- **翻译期间又打了字就不替换**，免得冲掉新打的字。
- **记住原文和译文**（[`memo` / `swap`][field]，第 244–258 行）：
  - 最近 20 对，只放在内存里；
  - 比较时去掉零宽字符、把连续空白并成一个；写进去以后读回来的样子也记下，因为编辑器会改空白和换行；
  - 框里是记着的译文 → 换回原文；是记着的原文、目标语言没变、上次译全了 → 直接换成译文；都不是 → 当新写的，重新翻译。
- **0.7.1 才发现的坑：写回去的方法比翻译本身更要紧**（[`viaEditor` / `replace`][field]，第 188–239 行）：
  - 现在的网页编辑器大多自己另存一份内容，比如 Slate、CKEditor 5，桌面上不少 Electron 聊天软件里也是这类编辑器；
  - 绕开它直接改界面上的字，框里看着换了，编辑器存的还是原文，再打一个字就变回去，**发出去的也是原文**；
  - 浏览器版现在是先让编辑器自己换，它不接再改界面上的字：
    1. 全选后等编辑器读进选区；
    2. 发一个“替换文字”的输入事件，就是输入法、拼写检查换词用的那种；
    3. 再试一次粘贴；
    4. 最后才直接改界面上的字。
  - 在 Slate、Lexical、ProseMirror、Quill、Draft.js、CKEditor 5、Trix 的示例编辑器上都试过。
- **读文字**：每段一个 `<p>` 的编辑器，按“一段一行”读，不然段落之间会多出空行，写回去变成空段落。

### 桌面版要做的（全新功能）

- **检测三次空格**：要在系统范围内听空格键。
  - 建议用 Raw Input（`RIDEV_INPUTSINK`，挂一个隐藏窗口），在 `hotkeys.py` 现有的 Qt 原生事件过滤器里接 `WM_INPUT`。
  - 它只听、不拦，不会拖慢别的软件的键盘输入。
  - 另一个办法是低级键盘钩子（`WH_KEYBOARD_LL`）：回调一慢，全系统打字都会卡，超时还会被 Windows 悄悄摘掉，有的游戏反作弊也会注意它。
  - 两种都不是注入，不违反“不往游戏里注入”的规矩。
- **输入法**：中文输入法下，空格可能是用来选字的，也可能打出全角空格（U+3000）。照浏览器版的办法，触发后先读文字、确认真的以三个空格结尾（`[  　]{3}$`）再动手。
- **读文字**：
  - 建议先用 UI Automation 读当前焦点控件（ValuePattern 或 TextPattern），能顺便用 TextPattern2 的光标范围判断光标在不在最后。这样不碰剪贴板。
  - 读不到再用 Ctrl+A、Ctrl+C。但用户的字会进剪贴板历史（Win+V）。
- **写回去**：建议**模拟 Ctrl+A、Ctrl+V 粘贴**，这就是 0.7.1 学到的东西。
  - 系统级的真粘贴，所有编辑器都按自己的规矩接，聊天软件的输入框也会真的变。
  - UI Automation 的 `SetValue` 就像浏览器里直接改界面上的字：Electron 和 Chromium 的输入框可能只是看着换了，发出去还是原文。
  - 放进剪贴板时带上不进剪贴板历史的格式（`ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory` = 0），粘完把用户原来的剪贴板内容放回去。
- **和浏览器扩展别撞车**：Chrome 和 Edge 里装了扩展的话，扩展也会响应三次空格，两边会各换一次。建议默认跳过浏览器窗口（chrome.exe、msedge.exe、firefox.exe 等），设置里可以改。
- **原文和译文只放内存**：照 0.7.1，最近 20 对，不写硬盘。这也符合“屏幕上的字要存进硬盘，必须用户自己打开”的规矩。用量日志照旧只记数量。
- **翻译**：直接用 `translator.stream_translate`，原文语言用母语，目标用新设置；批次和用量照现有逻辑计。
- **提示**：在光标附近（`GetGUIThreadInfo` 的光标位置，或焦点控件的范围）用现有的小提示窗显示同样几句话。
- **设置**：
  - “输入框翻译”开关，默认**关**；
  - “翻译成”的语言；
  - 不启用的程序列表；
  - 命令行和 AI 接口（#4）也能改。
- **测试**：
  - 单元测试：触发判断（间隔、连发、修饰键、行首）、记忆的规则（可以照搬 [tests/field.mjs](https://github.com/Yudreamsky/deskmirror-browser/blob/a8bc44ff9081e70562a0075c7b76b1e4888ee6b2/tests/field.mjs) 的各条）；
  - 实测：记事本（UI Automation 能读写）、一个 Electron 聊天软件（要走粘贴），以及微信、QQ、Telegram。

### 要拍板的

1. **做不做、什么时候做？** 这是最大的一块。建议在 A 之后单独开 issue 或 PR。
2. **听键盘用 Raw Input 还是低级键盘钩子？** 建议 Raw Input。
3. **读文字**：建议先用 UI Automation，读不到再用剪贴板。
4. **写回去**：建议模拟粘贴，不用 `SetValue`。
5. **默认关闭，并默认跳过浏览器？** 建议都要。
6. **要不要再给一个快捷键**（比如 Ctrl+Alt+T）当另一种触发方式？可选。

## C. 开机自启后以气泡状态待命（并进 #9）

- **浏览器版 0.7.0**：设置里打开“所有网页默认显示魔镜气泡”后，每个网页边上都有一个藏起一部分的气泡。
  - 点开之前不复制网页、不翻译，每个网页只多花 5–7 ms 脚本时间和约 2 ms 的气泡；
  - 点开才开始干活，关掉魔镜又缩回气泡。
- **桌面版**：#9 已经提到开机启动时可以直接收成气泡。建议：
  - 开机自启时**收成球吸在屏幕边上**，不截屏、不识别；
  - OCR 模型可以等第一次点开再加载，开机更快；
  - 点球或拖出来才开始工作。
- **要拍板**：开机自启以后的初始状态是球（建议）、暂停的魔镜，还是照常工作？

## D. 关掉魔镜时停掉在途请求

- 浏览器版关掉魔镜就丢掉这次的结果，所以没回来的请求直接停掉，白花的 token 就省了。
- 桌面版不一样：
  - 退出时 `TranslatorPool.close()` 已经会关掉连接、打断请求；
  - 暂停时，在途的请求照常回来、记进缓存和用量，继续以后接着用，不算白花。
- 建议**不改**。

## E. 不适用

### 液态玻璃皮肤（之后用户又要求的）

用户看了 A、B、C 以后要求“也要增加一个苹果液态玻璃效果皮肤，在边框几个像素有那种圆角玻璃的透射扭曲和拉伸”，于是把 #8 剩下的这一半也做了（`ui/glass.py`，设置里的 `style.skin`）。和浏览器版不一样的地方：

- **边框本身也折射**：浏览器版的镜框边线只是白线加阴影；桌面版的边框是镜框外一圈 11 px 的圆角玻璃（也是调整大小的抓取带），后面的画面在这一圈里往外拉宽、沿圆角弯过去，红绿蓝各偏一点。位移照“从边缘往里取样”那条（越靠外沿取得越远，一半匀速放大、一半按圆弧弯折，外沿往里 6.5 px）；取得再远，窄窄一圈会被拉成色条，像花屏。
- **后面的画面从截屏来**：浏览器能用 `backdrop-filter`，桌面版靠魔镜的窗口都对截屏隐身——引擎截屏的缓冲区里正好是它们后面的东西，直接复制要的那几条；引擎没在截时（暂停、收成球、别的屏）自己隔 0.25 秒截一小块。
- **桌面复制会把自己的重画也报成变化**（对截屏隐身的窗口也算），只看变化范围会玻璃重画、报告变化、再重画，停不下来；所以截到以后要和上次的画面比一比。
- 标签、球的深浅按后面的平均亮度自动换（白玻璃 / 烟灰玻璃，带回差），不跟系统的深色模式。
- 色键窗口（Windows 10）画不了半透明：玻璃先和后面的画面混好、整块不透明地画上去，边缘一样平滑；伸出这块范围的细描边不画，不然会混出洋红色。
- 变形途中（收成球、张开）是不折射的玻璃样子：每帧都改大小，来不及取样。球滑出、藏回时，开始滑之前把经过的那块背景截好，每帧从里面取样。

验收（`footage/record.py` 新加的 `glass` 场景，`MIRROR_SKIN=glass`）：深色游戏页、浅色文章页上存图看样子；静止的页面上玻璃几乎不重画（每轮检查约 0.6 ms）；游戏画面一直在动时每轮约 4 ms；滚动网页时边框跟着重画；色键窗口里没有洋红色漏出来；运行中改配置文件换皮肤，标签、边框的位置跟着变、换回经典和原来一样；`dock` 场景在玻璃皮肤下照样全过（每帧 16–18 ms）。拖着球离开边缘、识别重新启动的那一下有一帧 75–85 ms，经典样子也一样，不是皮肤带来的。
